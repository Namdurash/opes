# OPES-48 — Transactions category & month filter

The Transactions screen becomes a destination that can be opened pre-filtered by a category, a month, or both, so a future analytics drill-down (OPES-49) has somewhere to land and users can narrow a long history. Filtering is a pure in-memory selection in `useTransactionsViewModel` over the already-loaded transactions and category map — no new query, no new database read. The active filter is shown as one dismissible chip per dimension, each independently clearable, and the filter is ephemeral: any arrival without a payload shows the full list.

The behavioral contract this spec fixes — the widened route-param shape (AS-001) and the `YYYY-MM` prefix month rule (AS-002) — is the interface OPES-49's navigator must produce, so both tickets consume the same shape. Reviewers should check that shape and the resolution of the "identical payload after a manual clear" edge (AS-005) against product intent.
